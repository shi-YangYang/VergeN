# 切换订阅后的代理列表

**PASS（S2）。** 桌面端原先为所有订阅共用一份代理快照。切换完成后，如果新快照晚到，代理页仍能展示旧节点。修复后按已提交的订阅 UID 发起读取，并核对内核快照的归属；同订阅的常规刷新仍有效，失败或忙碌不推进选中的 UID。

- 用独立 Mihomo 实例与 Chrome、实际 AppDataProvider 和 SWR，在同名 FixtureGroup 中从 Node-A 切到 Node-B。测试桥模拟 IPC 的返回时机。修改前，内核已在 B 而界面仍可读到 A；修改后等待 B 的快照时展示加载，返回后显示 B。在只收到订阅变更、尚未收到单独代理刷新通知的场景，新版已主动读取 B，无需等 15 秒轮询。
- Android 对同名代理组、同名订阅标题的内容更新，原本不重新读取。用 JVM 运行真实 ProxyActivity，替代 Binder 和界面，在 ProfileLoaded 后读取的节点从原版 Node-A 变为 Node-B。恢复到前台时会补读，已过时的同组请求会取消。
- 桌面定向测试、TypeScript 检查和 ESLint 通过；独立审查通过。未使用生产订阅，未做 Android 真机或各桌面系统安装包的端到端测试。
