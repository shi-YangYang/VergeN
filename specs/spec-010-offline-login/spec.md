# 断网时保留钉钉登录入口

## 背景
Windows 断网启动曾出现报错，原文未知。桌面和 Android 的登录页在能力查询超时或失败时会锁住钉钉入口。

## 目标
登录页立即可操作。后台核实运维服务是否启用了钉钉；网络异常不改变上一次确认结果。

## 非目标
不提供离线认证，不改管理员开关、OAuth、密码登录和员工权限，不隐藏真正的本机启动故障。

## 当前行为
两个客户端均会自动查询，但上次确认的布尔值不跨启动保存。当前查询没有结果时，即使此前启用也可能无法选择钉钉。

## 目标行为
- 按运维服务分别保存最后一次明确返回的开关值。同一服务下次打开登录页先读取该值。断网、超时、服务错误或响应缺字段都不改写它；明确关闭会取代之前的启用，反之亦然。
- 每次进入登录流程在后台查询，首次算第 1 次，成功即停，总共最多 5 次。切换标签、切到后台再回来或网络变化不自动重置次数。员工可主动发起新一轮。
- 没有历史时不把未知当成管理员关闭：已配置服务器的员工仍可尝试钉钉登录。能点击入口并不代表拥有登录权限；申请二维码和完成授权仍由服务器决定。
- 选择钉钉才申请授权，失败在扫码区域提示，员工可原地重试或改用密码。密码页不显示后台探测报错。

## 功能需求
保留密码入口和桌面/Android 现有授权方式；查询失败不弹全局报错；离开或切换服务后，旧请求不应改变新的界面或登录会话。

## 边界条件
没有服务器地址时提示配置问题；明确关闭时不能完成扫码登录。仅修复可定位的离线启动错误来源，不把全部日志或本地故障都归为断网。

## 技术约束
缓存仅存开关值，不存账号或凭据。后台检查与认证请求分别管理次数及生命周期。

## 兼容性要求
Windows、macOS、Linux 共用桌面实现，Android 原生实现按相同规则处理。无需重新部署运维服务。

## 验收标准
- [ ] 上次启用/关闭在重启、连续断网后仍及时呈现；切换服务不串值，明确的新值可覆盖。
- [ ] 自动查询成功早停、失败最多发 5 次，第 5 次后不再自动请求；手动重试可恢复。
- [ ] 网络失败仅在登录操作对应的区域反馈；密码可用，服务端禁用和授权检查仍然有效。
- [ ] 真实日志或本机启动故障保持可诊断，未复现情况与已验证的路径分开报告。

## 待确认问题
Windows 原生弹窗的标题和第一行未取到，尚不能据此确认该机器的报错来源。
