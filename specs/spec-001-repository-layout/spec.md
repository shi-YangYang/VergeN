# 仓库目录整理

## 背景

维护者希望在 VergeN 接入统一的 Agent 规范，并让开发人员按功能找到源码、测试和环境配置。

## 目标

根目录只保留工程入口与必要说明，每个迁移文件都有清晰的归属和可运行的调用入口。

## 非目标

生产部署、产品交互、员工数据和签名密钥的修改均不在本次范围内。

## 当前行为

仓库根有模型专属说明、变更日志和环境文件。运维网页的发布测试、发布代码和下载页面分散在不同目录。

## 目标行为

根 Markdown 保留 README 和 AGENTS。贡献指南和隐私政策可从 README 访问。发布、下载与 iOS 功能按职责定位，工程命令能找到迁移后的测试和配置。

## 功能需求

- 删除根部模型专属说明和变更日志，同步更新消费者。
- 按功能归拢运维网页代码、发布测试与工具测试。
- 归拢环境示例及本机打包环境，补齐项目说明、规格模板与决策目录。

## 边界条件

在旧工作副本中，目标环境文件已存在时须避免覆盖；本地打包配置需保持原权限。

## 技术约束

沿用 Tauri、Gradle、Cargo 和 Go 的工程入口，保留 Go 包内测试及 Rust 原生测试布局。

## 兼容性要求

保留客户端和服务端的启动、登录、打包和发布入口，以及打包私有文件与进程环境变量的覆盖顺序。运维部署与客户端草稿打包继续分别手动触发。

## 验收标准

- [x] 根 Markdown 只保留 README 和 AGENTS，仍使用的文档和脚本链接可解析。
- [x] 移动后的业务代码能构建，Vitest 与 Node 继续发现并执行受影响测试。
- [x] 开发与构建命令能加载所需配置；本机私有配置未被提交或输出。
- [x] 发布工具、CI 和提交钩子不再依赖已删除文件。
- [x] 规范目录齐备，现有项目特有的分支、发布和客户端平台约束仍可找到。

## 待确认问题

当前整理范围已由维护者在本次请求中确认。
