# 公告下发与已读同步

**独立验收：PASS（S3，数据库迁移及员工会话）。**

## 已验证

- 下发 B 后，旧管理页面再停用 A、或请求启用已删除的 A，员工看到的仍是 B。切换失败不会留下半完成状态；未下发的草稿、重复确认和无变化的操作不改变 VPN 配置版本。
- 用两个登录会话验证同一员工已确认的版本不再下发，其他员工照常收到。旧版的确认即使在新版发布后到达，也不会隐藏新版。在 SQLite 中连续确认 300 个版本并重新打开数据库，最早的记录仍有效。
- 用实际 React 弹窗和本地 Go 服务模拟断网：点击后本机先隐藏，恢复连接补交后，另一浏览器的同一账号不再看到公告。实际 Android 网络客户端与同一服务协议也验证了迟到确认、撤回并重发。
- 桌面 StrictMode 首次挂载、焦点往返和轻量模式重建窗口合计仅一次 HTTP 首查。临时 401 与撤回区分，旧会话的请求不会污染新登录。1,000 次观察器卸载后无残留定时器、监听器或模拟会话对象；成功提交 1,000 条确认后无待交键。
- Android 不可交互时不消耗首查，首次解锁检查一次；前台计时在业务页面暂停时保留。用真实 OkHttp 和本地慢响应验证，原来 4 次退出后仍有 4 条在途请求，修复后 4 条均已取消。离线确认、写盘失败的网络兜底、双失败保留可重试状态已用 JVM 验证。

## 边界

本地验证，未部署到生产、未安装三平台发行包或执行 Android 真机堆分析。离线时其他设备不能获知刚做出的确认；升级前仅留在旧设备上的已读标记，也只有在旧设备和可识别的员工会话仍在时才有机会补交。
