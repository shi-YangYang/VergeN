# 实施方案

服务端在 SQLite 事务内切换当前下发的公告，仅员工可见公告实际变化时增加旧客户端所用配置版本。登记曾经下发的公告 ID 和内容版本，以便客户端在公告被编辑、撤回或删除后仍能补交当时的确认。

客户端读取 `GET /api/v1/client/announcement`。没有当前公告或该员工已确认时，返回 `{"announcement":null}`。点击「我知道了」后向 `POST /api/v1/client/announcement/ack` 提交 `id` 和 `revision`；服务端从现有客户端会话识别员工，对重复确认返回 204。未曾登记的版本返回 409，不能误确认当前新版。不改原有 bootstrap 协议。

桌面三端共用原生登录会话，Android 使用自己的企业会话。退出时清理请求和会话状态。离线确认仅按本机当前服务器与账号重试；服务端确认成功后清理本地待办。升级前遗留的本机标记不设淘汰上限。仅当升级时已有登录会话能确定其所属员工时，才迁移匹配的旧标记；同名新登录不会认领旧账号的记录。验证使用临时数据库和测试账号，不连接生产服务。
